# RAG-пайплайн (Retrieval-Augmented Generation)

## Этап 1: Индексация документа (Ingestion)
1. **Загрузка:** Файл сохраняется в общую директорию `/app/storage`.
2. **Парсинг:**
   - `.pdf` — построчное извлечение текста со всех страниц через `PyPDF2`.
   - `.docx` — чтение параграфов и таблиц через `python-docx`.
   - `.txt` — декодирование в UTF-8.
3. **Чанкинг (Chunking):**
   - Текст очищается от лишних пробелов и делится на фрагменты размером ~1000 символов с перекрытием (overlap) ~200 символов для сохранения контекста на стыках.
4. **Векторизация (Embeddings):**
   - Для каждого чанка вызывается модель эмбеддингов (`text-embedding-3-small`, размерность 1536).
5. **Суммаризация:**
   - Первые чанки (или агрегированный текст) отправляются в LLM для генерации структурированного конспекта в формате Markdown.

## Этап 2: Поиск и генерация ответа (Retrieval & Generation)
1. Пользователь отправляет вопрос по выбранному `document_id`.
2. Вопрос преобразуется в вектор тем же эмбеддером.
3. Выполняется SQL-запрос с оператором косинусного расстояния (`embedding <=> :query_embedding`) с выборкой Top-5 наиболее релевантных чанков.
4. Найденные чанки подставляются в системный промпт LLM со строгой инструкцией отвечать исключительно на основе предоставленного контекста.
